# links_new_projects_bot

Telegram-бот на Google Apps Script, який попереджає команду про нові проекти
з дедлайном на сьогодні — щоб про них дізнавались одразу, а не коли вже пізно.

Читає основну таблицю відділу, аркуші `Меджик - {Місяць}` і `ГП - {Місяць}`
(місяць українською підставляється автоматично).

## Файли

| Файл | Призначення |
|---|---|
| `novi_proekty_bot.gs` | увесь код бота; у проєкті Apps Script лежить як «Нові проекти бот» |

## Що робить

| Тригер | Що надсилає |
|---|---|
| 🔴 `checkUrgent` — кожні 5 хв | проекти, які щойно стали терміновими: дедлайн сьогодні |
| 🟡 `hourlyDigest` — 9:45 і щогодини 10:00–19:00 | дайджест дедлайнів на завтра/післязавтра |
| 📋 кнопка «Сьогоднішні ДДЛ» | стан на зараз: сьогоднішні ДДЛ, де Публікація ще не «Опубліковано» |
| 🧹 `nightCleanup` — 3:00 | видаляє всі повідомлення бота, щоб у чаті були тільки сьогоднішні |

Автоматичні розсилки йдуть лише в будні 9:30–19:30 (`isQuietTime`).
Кнопки адміна працюють завжди.

### Коли рядок вважається терміновим

Одночасно мають збігтися три умови:

- **Публікація** — «Заплановано» для Меджик, «Погоджено донорів» для ГП
- **Простір** — «на тул»
- **Дедлайн** — сьогодні

Статуси звіряються по початку рядка в нижньому регістрі (`заплановано`,
`погоджено донор`), щоб не залежати від точного тексту у випадному списку.

## Колонки

Резолвляться за назвами заголовків у **рядку 2**, з фолбеком на номери
з `COLS`. Меджик і ГП мають ідентичну структуру.

| Колонка | Заголовок |
|---|---|
| A | № |
| B | Замовник |
| H | Публікація |
| N | Дедлайн |
| S | Простір |

## Рішення, які неочевидні з коду

**Рядок-шапка.** Проект, розбитий на частини, має в таблиці рядок `840`
(агрегат, Публікація завжди порожня) і рядки `840/1`, `840/2` з реальними
статусами. Якщо частини є — статус береться лише з них. Інакше закритий
проект виглядав би як незакритий.

**Ключ пам'яті з датою.** Рядки групуються по baseId (`740/1` + `740/2` → `740`),
але в межах одного дня: ключ `{М|Г}{baseId}@{д.м}`. Тому поступовий проект,
розтягнутий на кілька дат, сповіщається заново в кожен свій день ДДЛ.
Пам'ять обнуляється зі зміною місяця.

**Номери-дати.** Номер на кшталт `2/19` Google Sheets перетворює на дату
(19 лютого). `formatProjectId` конвертує `Date` назад у «місяць/день».

**Ранковий дайджест о 9:45, а не 9:30.** Google зсуває погодинний тригер
на ±15 хв, тож 9:30 міг би впасти на 9:20 — у тишу.

**`poll` замість вебхука.** Команди приймаються через `getUpdates` з
`timeout=50`, тригер раз на хвилину, `LockService` проти паралельних запусків.
Один запуск живе до 4 хв — тому після правки коду тригери треба перевстановити,
інакше вже запущений `poll` ще кілька хвилин працює старою версією.

## Встановлення

1. Таблиця → **Розширення → Apps Script**, вставити `novi_proekty_bot.gs`
2. **Налаштування проєкту → Властивості скрипта** додати:

| Ключ | Значення |
|---|---|
| `BOT_TOKEN` | токен від @BotFather |
| `SHEET_ID` | ID основної таблиці з аркушами Меджик/ГП |
| `ADMIN_ID` | Telegram ID адміністратора |

3. Запустити `installTriggers` — вона знімає вебхук і створює всі тригери
4. Написати боту `/start`

Працівники додаються командою `/add ID`, прибираються `/del ID`, список — `/list`.

## Діагностика

| Функція | Що показує |
|---|---|
| `debugProject("840")` | усе, що бот бачить по конкретному проекту, і чи проходить він фільтри |
| `debugHeaders` | які колонки знайдені за заголовками рядка 2 |
| `resetNotified` | стирає пам'ять про вже надіслані сповіщення |

**Найчастіша плутанина.** Кнопка «📤 Розіслати термінові» записує всі поточні
проекти в пам'ять `NOTIFIED`, тож автоматика їх більше не повторює — виглядає
як «бот зламався». Лікується `resetNotified`. Врахуйте: ручний запуск
`checkUrgent` — це справжня розсилка всім підписникам, а не тест.
Тест — кнопка «👀 Термінові (тільки мені)».

## Секрети

Токен, `SHEET_ID` і `ADMIN_ID` живуть у Script Properties і в репозиторій
не потрапляють. `ADMIN_ID` у коді — нуль-заглушка, запасне значення на випадок
незаданої властивості.
